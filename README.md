# 骐骥看板 (Qiji Kanban Software)

## 一、概述

骐骥看板是一款适用于Windows系统的简洁任务管理看板工具。所有任务数据存储于本地数据库。内置 AI 助理，可将自然语言自动解析为结构化任务。

---

## 二、独特价值

### THEMRPR 任务框架

> “比起闷头去做，拆解思考一下会让任务更顺畅。”

每个任务围绕目标（Target & Purpose）、资源（Resource）、工期（Time Limit）、预期效果（Expectations）、注意要点（Hints）、实现路径（Methods）、相关方（Relevants）七个维度展开，从"记一笔"升级为"计划一次"。

### 智能子任务系统

> “知道自己正在做什么会对提升效率很有帮助。”

支持子任务依赖链（后序），并显示当前正在进行的子任务，完成一个自动跳转到下一个。子任务可独立设定属性，也可继承主任务，灵活不冗余。

### 双视图切换

> “无论喜欢按日期的列表还是按项目的卡片来管理任务，都不在话下。”

日期视图按天管理任务，项目视图以看板形式拖拽卡片。两个视图共享同一数据库，数据天然同步。

### AI 助理（基于DeepSeek API）

> “有事您说话，让AI帮您梳理任务。”

用自然语言描述任务，AI 自动拆解为 THEMRPR 结构化任务并预填表单。支持多任务一句话录入。

### 软件皮肤主题 + 免编译定制

> “用您心仪的皮肤来为您的任务管理增添快乐。”

软件内置深蓝、墨绿、暖橙、浅灰 4 套主题皮肤，切换即时生效。可自制软件皮肤，将自定义主题文件夹放入 `themes/` 目录，重启自动识别。

### 完整复盘工作流

> “积累也是任务价值的一部分。”

任务完成后填写复盘（计划 vs 实际），支持单任务和项目级别的 Markdown 复盘报告导出。

### “小即是大”

> “辩证法教导我们，看似不利的条件在一定范围内可以变成有利条件。”

正因放弃了过于冗杂的功能，整个软件足够轻量化，解压即用。

## 三、快速开始

### 安装与启动

1. 下载并解压 `qiji-kanban.zip`。
2. 双击 `QijiKanbanSoftware.exe` 启动。
3. 软件会自动启动服务端并打开界面。

**首次启动**会显示欢迎页，选择简易模式或详细模式后即可使用。日后可在设置中随时切换。

### 基本使用流程

1. 在日期视图中点击 **"+ 新建主任务"**，填写任务名称和详情。
2. 在详细模式下，可以为任务添加子任务，可以单独设置子任务的属性，子任务之间可设置**后序依赖**。
3. 选中子任务，点击 **"完成"** 或 **"放弃"**，系统自动跳转到下一个未完成子任务。
4. 左侧边栏点击**文件夹图标**切换到项目视图，拖拽卡片管理任务状态。
5. 已完成的任务可以点击 **"复盘"**，填写计划 vs 实际对比并导出 Markdown 报告。

## 四、技术栈

| 层级   | 技术                    | 说明                   |
| ------ | ----------------------- | ---------------------- |
| 桌面壳 | NW.js v0.88             | 独立窗口，系统原生体验 |
| 后端   | Express v4 + Node.js    | REST API，30+ 端点     |
| 数据库 | better-sqlite3 (SQLite) | 本地单文件，WAL 模式   |
| 前端   | React 19 + TypeScript   | 函数组件 + Hooks       |
| UI 库  | Ant Design 6            | 企业级组件库           |
| 拖拽   | @dnd-kit                | 项目视图看板拖拽       |
| AI     | DeepSeek API            | 自然语言 → 结构化任务  |
| 加密   | AES-256-GCM             | API 密钥本地加密存储   |
| 打包   | Webpack 5 + tsc         | 前端打包 + 服务端编译  |

### 数据库表

| 表                 | 说明                                |
| ------------------ | ----------------------------------- |
| `main_tasks`       | 主任务（含 THEMRPR 框架、项目名称） |
| `sub_tasks`        | 子任务（含后序依赖链）              |
| `daily_records`    | 每日任务记录（支持跨日继承）        |
| `progress_reports` | 进展报告（自动生成）                |
| `retrospectives`   | 复盘记录（计划 vs 实际）            |
| `settings`         | 系统设置（主题、模式、API 密钥等）  |

## 八、设计思路Q&A

如果您看到这里，请允许我向您再次致以最诚挚的谢意，这说明您开始关注骐骥看板的“灵魂”，您的这份关注是我极大的荣幸。

**Q：为什么这个软件叫“骐骥”？**

A：“骐骥”既是日行千里的良马，也与“奇迹”同音。于我而言，这款软件不仅是一个提升效率的工具，更是无数善意共同孕育的“奇迹”。我一直认为，相信奇迹是很重要的，同时也期待用这款软件将无数人对我的善意继续传递下去。

**Q：你是怎么想出THEMRPR框架的？**

A：THEMRPR框架来源于我的实际经验，我认为有些时候，一件任务迟迟没有开始，又或是在执行过程中返工不断，可能不是因为“不想做”，而是因为“不知该做什么”，于是我认为可以从THEMRPR的七个角度来思考问题，比如思考每一项任务的目的和目标来去做真正有价值的工作、在最开始时就思考好任务的预期效果来方便复盘、理解好需要注意的要点来避免中途踩坑、指定好接洽人来避免无休无止的推诿扯皮等等。
这个框架很可能还不够完美，但我相信用这个框架去思考会比一头雾水效率更高。也正因如此，尽管软件的任务表单有简易和详细模式可选，但我仍然非常推荐您使用详细模式来构建思考的网络，或许这能为您带来一些有益的启发。

**Q：为什么你会选择把这款软件做的很简单，而不是去对标拥有更丰富功能的其他产品？**

A：在斗兽棋里，大象可以击败几乎所有的其他生物，却唯独会被老鼠击败，与此同时，老鼠可以被几乎所有的其他生物击败，但却唯独可以击败大象。我相信，在一定的范围内，看似不利的条件可以被转化为有利条件，所谓的小，在一定的范围内可能反而是大，这种观点是我将这个软件做的比较简单的核心原因之一。

在开发之初，我思考过，作为仅有一个人的独立开发者，尽管现在有了AI工具帮了很大的忙，但坦诚来说，个人在很多方面的能力仍然十分有限，想在这样的情况下用软件的功能丰富性直接与成熟的同类产品相对抗是不太可能的，既然如此，那么就把轻量化和便捷性做到一个相对好的程度，同时体现一部分自己的理念就好了。我正是怀着这样的想法进行了骐骥看板的开发，做了很多减法，尽可能使这款软件在能够完成完整工作流的同时，保持相对较高的轻量化程度，如果您能喜欢就是最好了。

**Q：为什么没有集成番茄钟等常见日程管理软件所具备的功能？**

A：这方面有两点原因：一是番茄钟这个领域已经有很多前辈优秀的产品珠玉在前，方法论和产品都已经非常成熟，我作为一个初次尝试的新人可能无法再去做出一些创新与有价值的工作了，二是我倾向于认为，对一个任务而言，比起统计在其上面花费的专注时间，保证其完整的完成是更重要的，所以这款软件可能会更多的关注到“如何完成任务与子任务”上面。

再次感谢您使用骐骥看板软件，您的支持与鼓励是对我最大的奖赏。
