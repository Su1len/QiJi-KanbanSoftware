# 骐骥看板 — AI 解析测试用例

## 设计目标

验证 DeepSeek API 在真实工作场景下的自然语言解析能力。用例从"干净的结构化输入"过渡到"真实口语"，覆盖五大维度。

每个用例包含：输入文本、期望解析的关键字段、评估要点。

---

## 用例 1：信息散乱的口语

**场景**：用户被上级交代了一件多步骤、多依赖的复杂任务，一口气说出来，信息混杂。

**输入**：
> 张总让我今天下午三点之前把竞品分析报告交上去，主要是对比A公司和B公司的Q2财报，数据从市场部王姐那边要，做完先给李经理过一眼再发。

**期望解析**：
- `name`: 竞品分析报告
- `purpose`: 对比A公司和B公司的Q2财报
- `resources`: 市场部王姐（数据来源）
- `relevants`: 张总（下达）、李经理（审核）
- `hints`: 下午三点前完成、先给李经理过目再发
- `priority`: 7-8（有明确截止时间）

**评估要点**：
- 能否从"交上去"推导出这是提交类任务
- 能否区分张总（发起人）和李经理（审核人）的角色
- "三点之前"是否正确映射为高优先级

---

## 用例 2：模糊优先级与隐含 deadline

**场景**：用户用口头禅表达紧急性，不直接给数字，"不急但最好XX"是日常工作中的典型表述。

**输入**：
> 这件事不急，但最好这周内搞定。把上个月的客户反馈整理一下，挑几条有代表性的整理成表格，回头开会要用。

**期望解析**：
- `name`: 整理上个月客户反馈
- `content`: 挑选有代表性的反馈，整理成表格
- `duration`: 本周内
- `priority`: 4-5（"不急但最好这周"）
- `purpose`: 开会使用

**评估要点**：
- "不急但最好这周内"应给出中等优先级，而非最低
- "回头开会要用"应映射到 purpose 或 relevants
- "挑几条有代表性的"应出现在 content 或 hints 中

---

## 用例 3：多任务混杂

**场景**：用户一次性列出多项待办，AI 应当能识别出这是多个独立任务，而非一个任务的子步骤。

**输入**：
> 今天要搞三件事：1. 提交报销单；2. 约王总下周二下午开会讨论新项目预算；3. 把测试环境的数据库清理一下。

**期望解析**：
- 应返回一个主任务，`sub_tasks` 包含 3 项：
  1. `name`: 提交报销单
  2. `name`: 约王总下周二下午开会讨论新项目预算，`relevants`: 王总
  3. `name`: 清理测试环境数据库，`resources`: 测试环境
- 主任务 `name` 可为"今日待办"或三个任务的概括
- `status`: 进行中

**评估要点**：
- 是否识别出这是三个独立任务而非一个任务的子步骤
- 第二条的"下周二下午"是否能准确提取到相关字段
- 第三条的"测试环境"是否能识别为资源/环境信息

---

## 用例 4：极端口语与逻辑不清晰

**场景**：用户说话极度口语化，充满口头禅、指代不清、逻辑跳跃。这是 AI 解析能力的天花板测试。

**输入**：
> 哎那个啥，帮我把那个昨天的那个文档，就是关于那个客户投诉的那个，整理一下发给老张。

**期望解析**：
- `name`: 整理客户投诉文档并发给老张
- `content`: 整理昨天的客户投诉相关文档
- `relevants`: 老张
- `status`: 进行中

**评估要点**：
- 能否从"那个那个"的冗余信息中提取核心意图
- "昨天"是否能映射到相关时间字段
- "老张"是否能正确识别为相关方

---

## 用例 5：信息不全，需 AI 合理推断

**场景**：用户只给出最精简的指令，AI 需要用常识补全缺失字段。

**输入**：
> 明天前把周报交了。

**期望解析**：
- `name`: 提交周报（不可为空）
- `status`: 进行中
- `priority`: 6-7（有明确截止时间）
- `duration`: 1天（"明天前"）
- `purpose` / `content` / `hints` 等可为空

**评估要点**：
- 即便信息极少，`name` 是否仍能生成有意义的任务名
- "周报"是否被正确理解为周期性工作汇报（而非其他含义）
- 其余字段空白是否被正确处理（JSON 中为空字符串或 null）

---

## 评估标准

对每个用例，按以下维度评分（1-5）：

| 维度 | 说明 |
|------|------|
| 实体提取 | 人名、时间、资源等关键信息的准确度 |
| 字段映射 | 提取的信息是否放入了正确的 THEMRPR 字段 |
| 优先级推断 | 模糊表述下的优先级合理性 |
| 结构完整性 | 必填字段是否都已填充，可选字段的留空是否合理 |
| 子任务拆分 | （仅多任务用例）是否将混合任务正确拆分为子任务 |

---

## 使用方式

在 AI 功能优化的后续迭代中：
1. 逐个用例测试，记录原始响应 JSON
2. 对比期望解析，标注偏差
3. 根据偏差调整 AI system prompt
4. 回归测试确保已有用例不被破坏
